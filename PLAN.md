# План развития ZeroSynk — статус (2026-10-19)

## Выполнено (v1.4.0)

### 1. Контекстное меню «Отправить в ZeroSynk» ✅
- `ContextMenuService.cs`: регистрация в `HKCU\Software\Classes\*\shell\ZeroSynk` и `Directory\shell\ZeroSynk` (без админа). Ярлык с иконкой, `--send-interactive "%1"`.
- `UI/SendWindow.xaml/.cs`: компактное окно подтверждения — имя файла, размер, кнопки «Отправить»/«Отмена».
- Очередь `interactive-queue` в `%APPDATA%\ZeroSynk`: новый процесс кладёт файл, сигналирует уже запущенному инстансу, тот показывает SendWindow. Работает и при закрытом приложении (запуск, показ, отправка).
- Win11: пункт появится в «Показать дополнительные пункты» (классическое контекстное меню). Для быстрого меню нужен COM/sparse package — отложено.

### 2. Кастомное меню трея ✅
- `TrayManager.cs` переписан: OwnerDraw `ContextMenuStrip` — тёмный фон (#1C1C1E), hover, разделители, шрифт Segoe UI 9.5. Цвета совпадают с темой приложения.

### 3. Плавающий pill-dock навигация (Android) ✅
- `Root.kt`: нижняя навигация заменена на тёмный скруглённый pill-dock (`RoundedCornerShape(50)`, `#1C1C1E`), иконки без подписей, выбранная — увеличенная (scale 1.1) с белым цветом, невыбранная — серая (#8E8E93). Анимация через `animateFloatAsState`/`animateColorAsState`.

### 4. Отправка нескольких фото из галереи ✅
- `ShareTargetActivity.kt`: добавлен `takePersistableUriPermission` для каждого URI перед закрытием Activity — разрешения больше не теряются при мульти-выборе.

### 5. Автоочистка старых файлов на ПК ✅
- `AppController.CleanOldReceivedFiles()`: при получении нового файла удаляет предыдущие в папке сохранения (оставляет `KeepRecentBatches`, по умолчанию 1).
- Настройки: `AutoCleanReceived` (вкл по умолчанию), тумблер «Очищать старые файлы» на SettingsPage.

Номера соответствуют обсуждённому списку идей. Формат `- [ ]` для отметок прогресса.

## A. Критично — чинить в первую очередь
- [x] **1. Оффлайн-догрузка файлов.** `fileOffer` ушёл, телефона нет → при его `hello`
      pending-outbox НЕ переотправляется = файл потерян. Догружать при подключении.
      *(При `hello` ПК переотправляет весь pending-outbox; недокачанный при обрыве
      файл остаётся в очереди и переотправляется при следующем подключении.)*
- [x] **2. Сигнал `status started`.** Выключил синхронизацию на ПК → телефон навсегда
      «Не подключено». При включении на ПК слать `status started`, телефон переподключается.
      *(ПК шлёт `status started` при включении; телефон по нему возвращает
      «Подключено». При паузе ПК дополнительно шлёт `status stopped` на каждый `hello`.)*
- [x] **3. Очистка outbox.** `%TEMP%\ZeroSynk\outbox` растёт вечно — удаление после
      выдачи + TTL (например, 24 ч) для недоставленных.
      *(Файл удаляется после полной выдачи ответа; при обрыве — остаётся.
      При старте ПК недоставленное (< 24 ч) восстанавливается в очередь, старше —
      удаляется; TTL-сворачивание каждые 15 мин.)*
- [x] **4. Balloons при `ShowTrayIcon=false`.** Сейчас выключение иконки в трее убивает
      ВСЕ уведомления («файл получен», уведомления телефона). Разделить: иконка в трее ≠
      всплывающие уведомления.
      *(Новая настройка «Всплывающие уведомления» (`ShowNotifications`) + `Notifier`:
      при включённом трее — balloon, без него — WPF-тост `ToastWindow`.)*
- [x] **5. Автоочистка безопаснее + `KeepRecentBatches` в UI.** `AutoCleanReceived`
      стирает чужие файлы из папки сохранения; вывести кол-во хранимых батчей в настройки.
      *(Манифест `%APPDATA%\ZeroSynk\received-files.txt` — удаляются только
      полученные от телефона файлы; чужие не трогаются. «Хранить батчей» 0/1/2/3/5
      в настройках; retention-цикл уважает выключенную автоочистку.)*
- [x] **6. Версии/совместимость протокола.** ПК 1.4.0 vs Android 1.5.0; `proto: 1`
      пингуется, но никогда не проверяется — проверять при `hello` и предупреждать.
      *(Телефон шлёт `proto` в `hello`, ПК отвечает `proto` в `welcome`; обе стороны
      сверяют версию и предупреждают при расхождении.)*
- [x] **48. Разрешение записи для Android 8/9.** `WRITE_EXTERNAL_STORAGE` объявлено в
      manifest, но не запрашивается runtime — на API 26–28 запись в Download может падать.
      *(Запрос при первом старте `MainActivity` на API 26–28, один раз на установку.)*

## D. Медиа
- [x] **24. Прогресс-бар + seek в плеере** (в уведомлении телефона), обложка трека.
      Протокол `media` получил `position`/`duration` (сек) и `cover` (base64 сырой
      обложки, шлётся только при смене трека; `SyncServer` пере-подставляет кэш для
      опоздавших). Уведомление: `setProgress` + `setSubText(m:ss / m:ss)`, крупная
      обложка, seek-кнопки −10 с/+10 с, `.setSilent(true)` + throttling по 2 с
      (анти-репост MIUI).
- [x] **25. Громкость ±, стоп, «открыть папку трека на ПК»**, избранное.
      Громкость — медиа-ключи VK 0xAF/0xAE (в SMTC нет volume API); стоп —
      `TryStopAsync`; «папка трека» — best-effort поиск файла по названию в
      Music/Videos/Downloads/Desktop → `explorer /select`, иначе открыть Music.
      **Избранное не сделано:** в SMTC нет API favorite/like — обойти можно только
      через клавиши-эмуляцию по конкретному плееру, не переносимо.
- [x] **26. Обратное управление:** медиа ТЕЛЕФОНА управляется с ПК (сейчас только ПК→телефон).
      Новый `PhoneMedia`: `MediaSessionManager.getActiveSessions` (нужен уже
      существующий «Доступ к уведомлениям»), push `media origin=phone` раз в секунду,
      обложка из `METADATA_KEY_ALBUM_ART`; приём `mediaControl` → `TransportControls`
      (prev/toggle/seek/громкость). На ПК — карточка «Играет на телефоне» на Главной
      и тумблер «Медиа телефона → ПК» в настройках. «Стоп» на телефоне отдаёт
      `pause()` — `MediaSession.stop()` поддерживают единицы плееров.
- [x] **27. Карточка «что играет» на главном экране** телефона, а не только в пуше.
      `ServiceState.media` + `NowPlayingCard` на HomeScreen: обложка, прогресс,
      тайминг, кнопки −10/⏮/⏸/⏭/+10 и ряд Громкость−/Стоп/Громкость+/Папка трека.
